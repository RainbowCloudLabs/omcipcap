# OMCIPcap AI Diagnosis CLI Specification

**Status:** Implemented
**Version:** 2

---

## Purpose

The goal of the AI Diagnosis module is to combine existing `omcipcap`
analysis results with Large Language Models (LLMs) to assist engineers
during OMCI troubleshooting.

The first implementation focuses on **prompt construction** and
**provider abstraction**.

`omcipcap` remains responsible for protocol analysis.

The LLM is responsible for reasoning.

---

## Design Principles

The AI layer **MUST NOT** duplicate OMCI protocol parsing.

Instead, it consumes structured Markdown generated by existing
`omcipcap` commands.

Responsibilities:

```
PCAP
    │
    ▼
omcipcap
    │
    ├── check
    ├── mibdb
    ├── vlan-tbl
    ├── tcont-flow
    ├── topology
    ├── overview
    └── diff
    │
    ▼
Markdown Context
    │
    ▼
LLM
    │
    ▼
Diagnosis
```

## CLI

### List supported providers

```
omcipcap ai providers
```

Returns supported provider adapters.

No API key required.


### List available models

```
omcipcap ai models --provider PROVIDER
```

Examples:

```
omcipcap ai models --provider openai

omcipcap ai models --provider claude

omcipcap ai models --provider openrouter

omcipcap ai models --provider ollama
```

Provider authentication depends on the provider.

### Single PCAP Diagnosis

```
omcipcap ai diag \
    omci.pcap \
    --problem-md problem.md \
    --provider openrouter \
    --model anthropic/claude-opus-4.5 \
    --mib-json custom-me.json \
    --semantic-dir semantic/
```

Purpose:

Analyze one OMCI capture using AI.

Input:

- target PCAP
- user problem description
- AI provider
- model
- optional custom Managed Entity definitions (`--mib-json`)
- optional semantic extensions (`--semantic-dir`)

Custom Managed Entity definitions are loaded before semantic extensions, using
the same validation, loading, and error behavior as `omcipcap overview`. Both
are applied before overview Markdown is generated.

Generated context:

```
System Prompt

+

problem.md

+

overview Markdown
```

The exact prompt wording is intentionally left unspecified in this document.

### Golden Case Diagnosis

```
omcipcap ai diag-diff \
    failing.pcap \
    --golden-pcap golden.pcap \
    --problem-md problem.md \
    --provider openrouter \
    --model anthropic/claude-opus-4.5
```

Purpose

Compare a failing capture against a known-good capture.

Recommended assumptions:

- same OLT
- same ONU model
- same service configuration

The AI should determine why the golden capture succeeds while the failing
capture does not.

#### Context Selection

`omcipcap ai diag-diff` MUST always construct the AI diagnosis context using the
following sections, in this exact order:

1. Full Lifecycle Semantic MIB Diff
2. OMCIPcap Analysis of the Golden PCAP
3. OMCIPcap Analysis of the Target PCAP

```text
problem.md

+

Full Lifecycle Semantic MIB Diff

+

OMCIPcap Analysis of the Golden PCAP

+

OMCIPcap Analysis of the Target PCAP
```

The diagnosis system prompt is supplied separately by the AI Provider framework
and MUST NOT be embedded into the user prompt.

The semantic MIB diff MUST be generated from the complete observed MIB state of
both captures.

The implementation MUST NOT compare only the MIB Upload snapshot.

The implementation MUST use the full reconstructed MIB lifecycle obtained from
all observed OMCI operations.

The first section MUST be generated by:

```python
full_mib_data_diff = omciparser.get_mib_diff_data(
    target_full_mib,
    golden_full_mib,
)

diff_markdown = omcimd.render_diff_md(full_mib_data_diff)
```

The implementation MUST reuse the existing two-stage semantic diff pipeline.
It MUST NOT change the public signature of `omcimd.render_diff_md()`.


The final user prompt structure and section formatting are defined under
[Prompt Section Formatting](#prompt-section-formatting).

The semantic diff MUST appear before both overview reports so the AI can first
identify the semantic differences and then use the overview reports to
understand the complete provisioning behavior of each capture.

The Golden PCAP represents the expected working provisioning.

The Target PCAP represents the capture currently being diagnosed.

The semantic diff direction MUST always be:

```text
Target PCAP
    ↓
Golden PCAP
```

The AI MUST be able to interpret the semantic diff as follows:

- `old` values represent the Target PCAP
- `new` values represent the Golden PCAP
- `added` entries exist in the Golden PCAP but not in the Target PCAP
- `removed` entries exist in the Target PCAP but not in the Golden PCAP
- `modified` entries exist in both captures but contain different values

The implementation MUST NOT rely on the language model to infer the comparison
direction.

The comparison direction MUST be explicitly stated in the generated prompt.

The overview reports MUST remain unmodified and reuse the existing
`overview` Markdown generation implementation.

### Prompt Section Formatting

Both `omcipcap ai diag` and `omcipcap ai diag-diff` MUST use deterministic
Setext-style headings for the outer prompt sections.

The existing `compose_user_prompt()` implementation defines the required
formatting behavior for `omcipcap ai diag`:

```python
def compose_user_prompt(problem_prompt: str, overview_markdown: str) -> str:
    """Combine the user problem and generated overview into the provider prompt."""
    # Use Setext headings so user-authored Markdown may freely use ATX (`#`)
    # headings without conflicting with the outer prompt sections.
    return (
        "User-Reported Problem\n"
        "=====================\n\n"
        f"{problem_prompt.rstrip()}\n\n"
        "---\n\n"
        "OMCIPcap Analysis\n"
        "=================\n\n"
        f"{overview_markdown.rstrip()}\n"
    )
```

This implementation is the formatting reference for outer AI diagnosis prompt
sections.

`omcipcap ai diag-diff` MUST follow the same formatting style:

- use Setext headings for outer sections
- separate sections with `---`
- preserve embedded Markdown without rewriting it
- call `rstrip()` on embedded section content before concatenation
- terminate the composed prompt with exactly one newline
- keep section ordering deterministic

The implementation MUST NOT modify, normalize, demote, or renumber headings
inside:

- `problem.md`
- semantic MIB diff Markdown
- golden overview Markdown
- target overview Markdown

The `diag-diff` prompt composer SHOULD use a dedicated function that mirrors the
structure and formatting behavior of `compose_user_prompt()` rather than
constructing the prompt inline inside CLI code.

The final `diag-diff` user prompt MUST be equivalent to:

```text
User-Reported Problem
=====================

<problem.md content>

---

Full Lifecycle Semantic MIB Diff
================================

<render_diff_md(...) output>

---

OMCIPcap Analysis of the Golden PCAP
====================================

<golden overview Markdown>

---

OMCIPcap Analysis of the Target PCAP
====================================

<target overview Markdown>
```

The diagnosis system prompt is supplied separately through the AI Provider
framework and MUST NOT be embedded into the user prompt.

## Privacy

Cloud AI providers receive OMCI analysis data.

Users should remove:

- customer names
- serial numbers
- IP addresses
- credentials
- confidential deployment information

before sending data to cloud providers.

---

## Out of Scope

The first implementation does NOT include:

- prompt optimization
- prompt templates
- conversation history
- automatic retries
- tool calling
- cost estimation
- prompt caching
- automatic redaction
- AI-assisted command execution

These items may be implemented in future releases.
